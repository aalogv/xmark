# Оплот.X-Mark — сайт продукта

Сайт продукта Оплот.X-Mark (ООО «ОПЛОТ-ИТ»): невидимая маркировка экрана, по которой из скриншота или фотографии можно определить компьютер и время снимка.

Сайт подготовлен к подаче ПО в единый реестр российского ПО (Минцифры) и к требованиям к сайту аккредитованной ИТ-компании.

- Целевой адрес: https://xmark.oplot-it.ru
- Демо-стенд: https://xmark-demo.k3s.dex-it.ru
- Всё статическое, без сборки. Открывается напрямую или через любой HTTP-сервер.

## Структура

```
index.html            лендинг (экспорт бандлера, контент внутри JS-строки — правится скриптом)
company.html          сведения о правообладателе: реквизиты, ОКВЭД, ИТ-деятельность, продукты
price.html            стоимость и порядок её определения
privacy.html          политика обработки персональных данных (для формы на лендинге)
docs/index.html       оглавление документации + ссылки на PDF
docs/functional.html  описание функциональных характеристик
docs/requirements.html системные требования
docs/install.html     руководство по установке
docs/user-guide.html  руководство пользователя
docs/admin-guide.html руководство администратора
docs/lifecycle.html   процессы жизненного цикла и регламент техподдержки
docs/pdf/             PDF-версии документов (генерируются)
assets/site.css       общие стили статических страниц
scripts/patch-landing.py  точечные правки лендинга (идемпотентен)
scripts/build-pdf.sh      генерация PDF через headless Chrome
CNAME                 домен для GitHub Pages
```

## Запуск локально

```bash
python3 -m http.server 8765
# http://localhost:8765/
```

## Пересборка PDF

После правки любого `docs/*.html`:

```bash
scripts/build-pdf.sh          # нужен Google Chrome / Chromium
```

## Правки лендинга

`index.html` — экспорт из конструктора; разметка лежит в `<script type="__bundler/template">` как JSON-строка. Ручные правки там неудобны, поэтому изменения для реестра внесены скриптом:

```bash
python3 scripts/patch-landing.py --check   # что будет изменено
python3 scripts/patch-landing.py           # применить
```

Если лендинг пере-экспортирован из конструктора — просто запустите скрипт заново.

## Что нужно заполнить перед публикацией

Все места с непроверенными данными помечены в HTML блоком `class="todo"` (жёлтая плашка «Уточнить»). Найти: `grep -rn 'class="todo"' *.html docs/*.html`.

1. **Реквизиты** — сверить адрес (наличие «стр. 1») и основной ОКВЭД 62.02 с актуальной выпиской ЕГРЮЛ (`company.html`, футеры).
2. **Коды ИТ-деятельности** по приказу Минцифры № 449 (`company.html`).
3. **Стек разработки** (`company.html`).
4. **Версия ПО, класс по классификатору, почта техподдержки** — support@ или office@ (`docs/index.html`; support@ используется во всех документах).
5. **Матрица ОС**: точные версии Astra Linux SE и РЕД ОС, на которых пройдены испытания (`docs/requirements.html`). Это критично для правила двух ОС.
6. **Установка модуля ядра на Astra Linux SE**, уровни МКЦ (`docs/install.html`).
7. **Пороги стойкости метки** — минимальное разрешение, угол съёмки (`docs/functional.html`).
8. **Сроки реакции и решения техподдержки**, численность команды (`docs/lifecycle.html`).
9. **Прайс** — при наличии утверждённых цен добавить в `price.html`.
10. **Экземпляр ПО для экспертов** — постоянная ссылка на дистрибутивы и доступ к стенду (`docs/index.html`).

Технические детали в документации (имена пакетов, параметры MSI, команды `xmark-server`/`xmark-agent`, файл `server.yaml`, порты, REST API) написаны как целевая спецификация — сверить с реальным продуктом и поправить, где расходится.

## Публикация на xmark.oplot-it.ru

Вариант GitHub Pages:

1. Settings → Pages → Source: `main`, папка `/ (root)`. Для приватного репозитория нужен GitHub Pro; иначе сделать репозиторий публичным.
2. В DNS `oplot-it.ru` добавить `CNAME xmark → aalogv.github.io`.
3. Settings → Pages → Custom domain: `xmark.oplot-it.ru`, включить Enforce HTTPS. Файл `CNAME` уже в репозитории.

Вариант собственного хостинга: скопировать содержимое репозитория в корень веб-сервера, HTTPS обязателен.

## Вне репозитория

- На корпоративном сайте oplot-it.ru также должны быть реквизиты по приказу № 511 (для аккредитации).
- Демо-стенд размещён на домене dex-it.ru — эксперты могут спросить о принадлежности; лучше перенести на поддомен oplot-it.ru.
- Для заявления отдельно нужны документы о правах на ПО (свидетельство Роспатента или договоры с разработчиками).
