# Оплот.X-Mark — сайт продукта

Сайт продукта Оплот.X-Mark (ООО «ОПЛОТ-ИТ»): невидимая маркировка экрана, по которой из скриншота или фотографии можно определить компьютер и время снимка.

Сайт подготовлен к подаче ПО в единый реестр российского ПО (Минцифры) и к требованиям к сайту аккредитованной ИТ-компании.

- Целевой адрес: https://xmark.oplot-it.ru
- Демо-стенд: https://xmark2.oplot-it.ru:8080
- Всё статическое, без сборки. Открывается напрямую или через любой HTTP-сервер.

## Структура

```
index.html            лендинг (экспорт бандлера, контент внутри JS-строки — правится скриптом)
company.html          сведения о правообладателе: реквизиты, ОКВЭД, ИТ-деятельность, продукты
price.html            стоимость и порядок её определения
privacy.html          политика обработки персональных данных (для формы на лендинге)
docs/index.html       оглавление документации + ссылки на PDF
docs/functional.html  описание функциональных характеристик
docs/requirements.html системные требования
docs/install.html     руководство по установке
docs/user-guide.html  руководство пользователя
docs/admin-guide.html руководство администратора
docs/lifecycle.html   процессы жизненного цикла и регламент техподдержки
docs/pdf/             PDF-версии документов (генерируются)
assets/site.css       общие стили статических страниц
scripts/patch-landing.py  точечные правки лендинга (идемпотентен)
scripts/build-pdf.sh      генерация PDF через headless Chrome
scripts/regru-dns.sh      DNS у reg.ru через REG.API v2 (list / switch-to-pages / check)
CNAME                 домен для GitHub Pages
```

## Запуск локально

```bash
python3 -m http.server 8765
# http://localhost:8765/
```

## Пересборка PDF

После правки любого `docs/*.html`:

```bash
scripts/build-pdf.sh          # нужен Google Chrome / Chromium
```

## Правки лендинга

`index.html` — экспорт из конструктора; разметка лежит в `<script type="__bundler/template">` как JSON-строка. Ручные правки там неудобны, поэтому изменения для реестра внесены скриптом:

```bash
python3 scripts/patch-landing.py --check   # что будет изменено
python3 scripts/patch-landing.py           # применить
```

Если лендинг пере-экспортирован из конструктора — просто запустите скрипт заново.

## Что проверено, что придумано

Реквизиты (наименование, адрес, ИНН/КПП/ОГРН, ОКВЭД основной и дополнительные) — по выписке ЕГРЮЛ от 04.02.2026. Версия ПО — 0.93. Команда — 3 человека.

Написано как целевая спецификация, **на вычитку техническому директору**:

- `docs/functional.html` — функции агента и панели, пороги стойкости (разрешение ≥ 25 % экрана, угол до 45°), нагрузка (CPU < 1 %, ОЗУ до 50 МБ).
- `docs/requirements.html` — матрица ОС (Astra Linux SE 1.7/1.8, РЕД ОС 7.3/8, Альт 10/11, Ubuntu 22.04/24.04, Debian 12, Windows 10/11, Server 2016–2025), ресурсы сервера, порты.
- `docs/install.html` — имена пакетов, параметры MSI (`SERVER_URL`, `ENROLL_TOKEN`, …), команды `xmark-server` / `xmark-agent`, установка на Astra с МКЦ/ЗПС и DKMS.
- `docs/admin-guide.html` — `server.yaml`, REST API, формат CEF, коды возврата инсталлятора.
- `docs/lifecycle.html` — сроки реакции/решения (стандартная сетка 4 уровней), роли трёх сотрудников.
- `company.html` — стек (C++/WDK, модуль ядра Linux, Go, TypeScript/React, PostgreSQL), коды ИТ-деятельности 1.01 / 1.08 / 2.01 по приказу № 449, класс ПО «Средства защиты от НСД».
- Почта техподдержки `support@oplot-it.ru` — завести ящик или алиас на office@.

Перед подачей заявления добавить в `docs/index.html` постоянную ссылку на дистрибутивы и доступ к стенду для экспертов.

## Публикация на xmark.oplot-it.ru

GitHub Pages включён: источник — ветка `main`, корень; custom domain `xmark.oplot-it.ru` (файл `CNAME`). Каждый push в `main` публикуется автоматически за 1–2 минуты.

DNS у reg.ru (ns1/ns2.reg.ru). В зоне `oplot-it.ru` сейчас есть A-запись `xmark → 51.38.26.253` (k3s). Её нужно заменить:

1. reg.ru → Домены → `oplot-it.ru` → Управление зоной DNS.
2. Удалить A-запись с subdomain `xmark`.
3. Добавить запись: тип **CNAME**, subdomain `xmark`, значение `aalogv.github.io.` (с точкой в конце, если поле требует FQDN), TTL по умолчанию.
4. Подождать 5–30 минут, проверить: `dig +short xmark.oplot-it.ru` должен вернуть `aalogv.github.io.` и IP GitHub (185.199.108–111.153).
5. GitHub → репозиторий → Settings → Pages: дождаться «DNS check successful», включить **Enforce HTTPS** (сертификат Let's Encrypt выпускается автоматически, до часа).

Проверка после переключения: `curl -sI https://xmark.oplot-it.ru/docs/ | head -1` → `HTTP/2 200`.

То же через REG.API v2 (`scripts/regru-dns.sh`, учётные данные только в переменных окружения):

```bash
# один раз: reg.ru → Настройки → Безопасность → API — разрешить доступ, добавить свой IP
export REGRU_USER='логин' REGRU_PASS='пароль или альтернативный пароль API'
scripts/regru-dns.sh list              # посмотреть зону
scripts/regru-dns.sh switch-to-pages   # удалить A xmark, добавить CNAME → aalogv.github.io
scripts/regru-dns.sh check             # dig + HTTPS
```
