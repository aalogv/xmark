1. Конфигурация сервера

Основной файл конфигурации — /etc/xmark/server.yaml (в контейнерном варианте — переменные окружения в .env с теми же именами в верхнем регистре и префиксом XMARK_). После изменения выполните sudo systemctl restart xmark-server.

server:
  host: xmark.corp.local
  listen: 0.0.0.0:443
  tls:
    cert: /etc/xmark/tls/server.crt
    key:  /etc/xmark/tls/server.key
database:
  dsn: postgres://xmark:***@127.0.0.1:5432/xmark?sslmode=disable
agents:
  heartbeat_interval: 60s      # период отправки состояния агентом
  offline_threshold: 24h       # порог статуса «Нет связи»
analysis:
  snapshot_retention: 365d     # срок хранения загруженных снимков
  max_upload_mb: 50
session:
  idle_timeout: 30m
  password_policy: { min_length: 12, require_digits: true, require_mixed_case: true }
time:
  timezone: Europe/Moscow

Проверить конфигурацию без перезапуска: sudo xmark-server check-config.

1.1. TLS-сертификат

Рекомендуется сертификат внутреннего удостоверяющего центра организации. Корневой сертификат УЦ должен быть установлен на рабочих станциях (стандартными средствами ОС) либо передан агенту параметром CA_CERT при установке. Самоподписанный сертификат допустим для пилота.

2. Пользователи, роли, аутентификация

Раздел Настройки → Пользователи. Роли: Администратор, Оператор экспертизы, Наблюдатель (описание — в руководстве пользователя).

  • Локальные учётные записи: создание, сброс пароля, блокировка. Действует парольная политика из конфигурации.
  • Доменная аутентификация (LDAP / Active Directory / ALD Pro): Настройки → Аутентификация — адрес сервера, базовый DN, учётная запись для чтения, сопоставление групп домена ролям панели. Пользователи домена входят своими учётными данными; локальный администратор сохраняется как аварийный.
  • Все входы и действия фиксируются в журнале аудита.

3. Группы и политики маркировки

Раздел Рабочие станции → Группы. Для каждой группы задаются:

  • Интенсивность метки — стандартная (по умолчанию) или усиленная для помещений с ожидаемой фотосъёмкой под большим углом (усиленная интенсивность остаётся незаметной для глаза, но повышает стойкость при пересъёмке);
  • Защита от удаления — требовать код деинсталляции;
  • Порог «Нет связи» — переопределение глобального значения (например, для ноутбуков выездных сотрудников);
  • Автообновление агентов — разрешить обновление по команде из панели.

Изменение политики применяется агентами при следующем heartbeat (по умолчанию в течение минуты).

4. Интеграция с каталогом

Настройки → Каталог. Панель периодически (по умолчанию раз в час) читает из LDAP-каталога компьютеры и пользователей и сопоставляет их с зарегистрированными агентами по имени компьютера. Так в карточке станции автоматически появляются подразделение и ответственный пользователь. Поддерживаются Microsoft Active Directory, ALD Pro, Samba DC, FreeIPA. Возможен импорт из CSV (hostname;department;owner).

5. Выгрузка событий в SIEM

Настройки → Интеграции → Syslog: адрес приёмника, протокол (UDP / TCP / TLS), формат (CEF или JSON). Передаются события: регистрация и потеря связи агента, отключение маркировки, попытка вмешательства, выполненный анализ с результатом, действия администраторов. Пример события CEF:

CEF:0|Oplot|XMark|0.93|ANALYSIS_MATCH|Метка обнаружена|5|
  src=WKS-0417-MSK cs1=Отдел аналитики rt=1758025927000 suser=operator1 cn1=98

6. REST API

API доступен по адресу https://<панель>/api/v1/, аутентификация — токен API (Настройки → API-токены), передаётся в заголовке Authorization: Bearer <токен>. Основные методы:

МетодНазначение
GET /workstationsСписок рабочих станций с фильтрами
GET /workstations/{id}Карточка станции и события
POST /analysisЗагрузка снимка (multipart) и запуск анализа
GET /analysis/{id}Результат анализа
GET /analysis/{id}/reportОтчёт PDF
POST /enroll-tokensСоздание токена развёртывания
GET /healthСостояние сервера (для мониторинга)

Полная спецификация OpenAPI доступна в панели: Настройки → API → Спецификация.

7. Резервное копирование и восстановление

Резервному копированию подлежат: база данных PostgreSQL, каталог снимков /var/lib/xmark/snapshots, конфигурация /etc/xmark/ (включая TLS-ключи и файл лицензии).

# Резервная копия (встроенная команда: дамп БД + файлы в один архив)
sudo xmark-server backup /backup/xmark-$(date +%F).tar.gz

# Восстановление на чистом сервере после установки пакета
sudo xmark-server restore /backup/xmark-2026-09-16.tar.gz
sudo systemctl restart xmark-server

Рекомендуемая периодичность — ежедневно; команду можно поставить в cron. Критично сохранить БД: в ней хранятся идентификаторы рабочих станций и ключи маркировки — без них снимки, сделанные до потери базы, не могут быть сопоставлены с компьютерами.

8. Мониторинг и журналы

  • Состояние сервера: GET /api/v1/health (200 — исправен), метрики Prometheus на /metrics (число агентов по статусам, очередь анализа, время отклика).
  • Журналы сервера: journalctl -u xmark-server или /var/log/xmark/server.log; уровень задаётся ключом log.level (info / debug).
  • Журналы агента: Windows — %ProgramData%\Oplot\XMark\agent.log и журнал приложений Windows (источник XMarkAgent); Linux — journalctl -u xmark-agent.
  • Журнал аудита панели: Настройки → Журнал аудита, экспорт в CSV.

9. Диагностика неисправностей

СимптомПричинаДействие
Агент установлен, но не появляется в панелиНет сети до сервера / не доверен сертификат / неверный токенxmark-agent status, проверить curl -v https://<панель>/api/v1/health со станции, проверить журнал агента, при необходимости повторить xmark-agent enroll
Статус «Маркировка отключена»Драйвер не загружен (обновление ОС/ядра, несовместимый видеодрайвер)Linux: dkms status, пересобрать модуль; Windows: проверить подпись драйвера в диспетчере устройств; перезапустить службу
Статус «Без лицензии»Превышено число рабочих мест или истёк срокНастройки → Лицензия; удалить неиспользуемые станции или расширить лицензию
Снимок со станции не декодируетсяАгент на момент снимка не работал; сильное искажениеПроверить журнал станции за указанное время; повторить с исходным файлом
Время в результатах смещеноРассинхронизация часов сервераНастроить NTP на сервере панели (timedatectl), проверить time.timezone
Панель недоступна, 502Служба остановлена / СУБД недоступнаsystemctl status xmark-server, journalctl -u xmark-server -n 200, проверить доступность PostgreSQL

Для обращения в поддержку соберите диагностический архив: sudo xmark-server support-bundle (сервер) или xmark-agent support-bundle (станция) — журналы, конфигурация без секретов, версии компонентов.

10. Коды возврата инсталлятора

КодЗначение
0Успешно
1602 / 1603Установка отменена / общая ошибка MSI — см. журнал /l*v
3010Успешно, требуется перезагрузка (только при обновлении драйвера)
10Не указан SERVER_URL или ENROLL_TOKEN
11Сервер недоступен при регистрации (агент установлен, регистрация будет повторяться автоматически)
12Токен недействителен или отозван
13ОС или ядро не поддерживаются
