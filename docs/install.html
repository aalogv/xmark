1. Порядок развёртывания

  1. Убедиться, что инфраструктура соответствует системным требованиям.
  2. Установить сервер панели управления и СУБД.
  3. Активировать лицензию.
  4. Создать токен развёртывания.
  5. Установить агенты на рабочие станции — вручную на пилотной группе, затем централизованно.
  6. Проверить статус агентов в панели и провести контрольный анализ снимка.

Пилотное развёртывание на 10–20 рабочих станциях рекомендуется перед массовой установкой.

3. Установка сервера панели управления

3.1. Вариант A — пакет DEB/RPM (рекомендуется для Astra Linux и РЕД ОС)

# Astra Linux / Debian / Ubuntu
sudo apt install ./xmark-server_0.93.x_amd64.deb

# РЕД ОС
sudo dnf install ./xmark-server-0.93.x.x86_64.rpm

Пакет устанавливает службу xmark-server, локальный экземпляр PostgreSQL (если не отключено) и мастер первичной настройки. Запустите его:

sudo xmark-server setup
# Мастер запросит:
#  - доменное имя панели (например, xmark.corp.local)
#  - TLS-сертификат и ключ (или создаст самоподписанный)
#  - параметры СУБД (локальная / внешняя: хост, порт, БД, пользователь)
#  - логин и пароль первого администратора
sudo systemctl enable --now xmark-server

3.2. Вариант B — контейнеры

tar xzf xmark-server-0.93.x.tar.gz && cd xmark-server
cp .env.example .env          # заполнить XMARK_HOST, XMARK_DB_*, XMARK_ADMIN_PASSWORD
docker compose up -d
docker compose exec server xmark-server setup --non-interactive

Для Kubernetes в каталоге k8s/ приложены манифесты (Deployment, Service, Ingress, PVC) и values для Helm.

3.3. Внешняя СУБД

При использовании выделенного PostgreSQL / Postgres Pro создайте базу и пользователя, затем укажите их в мастере или в /etc/xmark/server.yaml:

CREATE USER xmark WITH PASSWORD '...';
CREATE DATABASE xmark OWNER xmark ENCODING 'UTF8';

3.4. Первый вход

Откройте https://<имя-панели>/ в браузере, войдите под администратором, созданным на этапе настройки. Проверьте синхронизацию времени сервера с NTP: корректность меток времени зависит от точности часов сервера.

4. Активация лицензии

  1. В панели: Настройки → Лицензия → Загрузить файл. Выберите файл xmark.lic, полученный от ООО «ОПЛОТ-ИТ».
  2. Или из командной строки сервера: sudo xmark-server license install /path/xmark.lic.
  3. В разделе «Лицензия» отобразятся организация, число лицензированных рабочих мест, срок действия и уровень поддержки.

Активация не требует доступа в Интернет: лицензия привязана к организации и проверяется локально. При превышении числа рабочих мест новые агенты регистрируются со статусом «Без лицензии» и не выполняют маркировку — панель выводит предупреждение.

5. Токен развёртывания агентов

Агенты регистрируются на сервере по токену развёртывания. В панели: Рабочие станции → Токены → Создать. Укажите название (например, «Пилот, бухгалтерия»), группу по умолчанию и срок действия. Скопируйте значение токена — оно понадобится в параметрах установки. Токен можно отозвать в любой момент; уже зарегистрированные агенты продолжат работу.

6. Установка агента на Windows

6.1. Интерактивно

Запустите xmark-agent-0.93.x-x64.msi от имени администратора, укажите адрес сервера и токен развёртывания. После завершения перезагрузка не требуется; агент стартует как служба XMarkAgent, драйвер загружается автоматически.

6.2. Тихая установка

msiexec /i xmark-agent-0.93.x-x64.msi /qn /norestart ^
  SERVER_URL=https://xmark.corp.local ^
  ENROLL_TOKEN=<токен> ^
  GROUP="Бухгалтерия"
ПараметрОбязателенОписание
SERVER_URLдаАдрес панели управления
ENROLL_TOKENдаТокен развёртывания
GROUPнетГруппа рабочих станций в панели
CA_CERTнетПуть к корневому сертификату, если сервер использует внутренний ЦС
PROXYнетHTTP-прокси для связи с сервером

Журнал установки: msiexec ... /l*v C:\Windows\Temp\xmark-install.log.

7. Установка агента на Linux

# Astra Linux / Debian / Ubuntu
sudo apt install ./xmark-agent_0.93.x_amd64.deb

# РЕД ОС
sudo dnf install ./xmark-agent-0.93.x.x86_64.rpm

# Регистрация на сервере
sudo xmark-agent enroll --server https://xmark.corp.local --token <токен> --group "Бухгалтерия"
sudo systemctl enable --now xmark-agent

Параметры можно передать без интерактивного шага через файл /etc/xmark/agent.conf или переменные окружения XMARK_SERVER_URL, XMARK_ENROLL_TOKEN при установке пакета — тогда регистрация выполняется автоматически в post-install.

На системах с включённым мандатным контролем целостности (МКЦ) установка выполняется из сессии с высоким уровнем целостности (63); пакет подписан и включает необходимые метки. Замкнутая программная среда (ЗПС): подпись пакета совместима с ЗПС, ключ поставляется в составе дистрибутива (oplot-xmark.gpg).

Для Альт используйте RPM-пакет: apt-get install ./xmark-agent-0.93.x.x86_64.rpm.

8. Централизованная установка

8.1. Групповые политики Active Directory (GPO)

  1. Скопируйте MSI в сетевую папку, доступную компьютерам домена на чтение.
  2. Создайте файл трансформации xmark.mst с параметрами SERVER_URL и ENROLL_TOKEN (утилита xmark-mst.exe из дистрибутива) либо задайте параметры в agent.json рядом с MSI.
  3. В консоли управления групповыми политиками: Конфигурация компьютера → Политики → Конфигурация программ → Установка программ → Назначенный пакет, укажите MSI и трансформацию.
  4. Агент установится при следующей загрузке компьютеров.

8.2. Kaspersky Security Center, SCCM и аналоги

Создайте инсталляционный пакет из MSI с параметрами командной строки из п. 6.2 и задачу удалённой установки на нужную группу устройств.

8.3. Ansible / Puppet (Linux)

ansible-playbook -i inventory.ini ansible/agent.yml \
  -e xmark_server_url=https://xmark.corp.local \
  -e xmark_enroll_token=<токен> \
  -e xmark_group="Инженеры"

Роль определяет дистрибутив, устанавливает DEB или RPM, регистрирует агента и включает службу. Пример манифеста Puppet — в ansible/puppet-example.pp.

8.4. Собственные скрипты

Silent-инсталлятор возвращает код 0 при успехе; коды ошибок описаны в руководстве администратора.

9. Проверка работоспособности

  1. На рабочей станции: xmark-agent status (Linux) или "C:\Program Files\Oplot\XMark\xmark-agent.exe" status (Windows) — должно выводиться marking: active, server: connected.
  2. В панели: Рабочие станции — компьютер отображается со статусом «Активен» и временем последнего контакта не старше 5 минут.
  3. Сделайте скриншот рабочего стола станции, загрузите его в Анализ снимка: система должна определить имя компьютера, пользователя и время с точностью до минуты.
  4. Повторите проверку с фотографией экрана, сделанной на смартфон.

10. Обновление и удаление

  • Сервер: установите новый пакет поверх (apt install ./xmark-server_0.93.y_amd64.deb / dnf upgrade) или обновите образы (docker compose pull && docker compose up -d). Миграции БД выполняются автоматически; перед обновлением сделайте резервную копию (см. руководство администратора).
  • Агенты: из панели (Рабочие станции → Обновить агент) или теми же средствами распространения, что и при установке. Новая версия MSI обновляет предыдущую без удаления.
  • Удаление агента: Windows — «Программы и компоненты» или msiexec /x xmark-agent-0.93.x-x64.msi /qn; Linux — apt remove xmark-agent / dnf remove xmark-agent. Удаление требует прав администратора; если в политике включена защита от удаления, необходимо указать код деинсталляции из панели: UNINSTALL_CODE=<код>.
